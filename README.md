# Conference Room Booking API

RESTful API для управління конференц-залами та бронюваннями, автоматичного розрахунку вартості оренди з урахуванням часових коефіцієнтів і формування аналітичних звітів.

---

## Технологічний стек

- **Платформа:** .NET 10 / ASP.NET Core Web API
- **Мова:** C# 14
- **База даних:** PostgreSQL
- **ORM:** Entity Framework Core
- **Валідація:** FluentValidation
- **Документація API:** Swagger / OpenAPI

---

## Архітектура проєкту

Проєкт розділений на три шари:

- **`ConferenceBooking.API`** — презентаційний шар (Controllers, Middlewares, конфігурація Swagger, `Program.cs`).
- **`ConferenceBooking.BLL`** — шар бізнес-логіки (Services, DTOs, `BookingPriceCalculator`, Validators).
- **`ConferenceBooking.DAL`** — шар доступу до даних (Entities, `AppDbContext`, Migrations, `DbInitializer`).

## Бізнес-логіка та ціноутворення

### Розрахунок вартості оренди (`BookingPriceCalculator`)

Вартість оренди розраховується окремо для кожної години інтервалу бронювання із застосуванням відповідного часового коефіцієнта:

| Часовий інтервал | Категорія | Коефіцієнт / Знижка |
| :--- | :--- | :--- |
| **06:00 – 09:00** | Ранкові години | **-10%** (множник `0.9`) |
| **09:00 – 18:00** | Стандартні години | **Базова ціна** (множник `1.0`) |
| **12:00 – 14:00** | Пікові години | **+15%** (множник `1.15`) |
| **18:00 – 23:00** | Вечірні години | **-20%** (множник `0.8`) |

> **Формула підсумкової вартості:**  
> `Загальна вартість = Σ (Базова ціна за годину × Коефіцієнт години) + Σ (Ціна обраних послуг)`

## API Endpoints

### Зали (`/api/rooms`)

- `POST /api/rooms` — створення нового залу з прив'язкою доступних послуг.
- `PUT /api/rooms/{id}` — оновлення даних про зал (ціна, місткість, назва).
- `DELETE /api/rooms/{id}` — м'яке видалення залу (Soft Delete).
- `GET /api/rooms/available` — пошук вільних залів за датою, часом і необхідною місткістю.

### Бронювання (`/api/bookings`)

- `POST /api/bookings` — створення бронювання з перевіркою доступності залу та автоматичним розрахунком вартості.

### Аналітика та звіти (`/api/reports`)

- `GET /api/reports/revenue` — фінансовий звіт за період (виручка від оренди залів і додаткових послуг).
- `GET /api/reports/amenities` — звіт про популярність і прибутковість додаткових послуг (кількість замовлень і загальна сума).

## Початкові дані (`DbInitializer`)

Під час першого запуску застосунку автоматично застосовуються EF Core міграції та заповнюються початкові тестові дані для демонстрації роботи системи:

### Зали

- **Зал A** — місткість 50 осіб, базова ціна 2000 грн/год.
- **Зал B** — місткість 100 осіб, базова ціна 3500 грн/год.
- **Зал C** — місткість 30 осіб, базова ціна 1500 грн/год.

### Додаткові послуги

- **Проєктор** — 500 грн.
- **Wi-Fi** — 300 грн.
- **Звук** — 700 грн.

### Тестові бронювання

Створюються історичні бронювання за серпень–вересень 2026 року для демонстрації роботи аналітичних звітів.

## Тестування

Для тестування бізнес-логіки використовується **xUnit** та **Moq**.

Тести `BookingService` покривають основні сценарії створення бронювання:

- успішне створення бронювання без додаткових послуг;
- успішне створення бронювання з додатковими послугами;
- зал не знайдено;
- час бронювання перетинається з існуючим бронюванням;
- додаткова послуга недоступна для обраного залу;
- додаткова послуга не існує.

Залежності `BookingService` ізолюються за допомогою `Moq`, що дозволяє тестувати бізнес-логіку без реального підключення до бази даних.

### Запуск тестів

Для запуску unit-тестів виконайте:

```bash
dotnet run --project ConferenceBooking.BLL.Tests
````

## Запуск проєкту

### Вимоги

Перед запуском необхідно встановити:

- .NET 10 SDK
- PostgreSQL

### Налаштування бази даних

1. Переконайтеся, що локальний PostgreSQL запущений.
2. Налаштуйте connection string у `appsettings.json` або за допомогою .NET User Secrets:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=HOST;Database=DATABASE;Username=USERNAME;Password=PASSWORD"
  }
}
````

Замініть `HOST`, `DATABASE`, `USERNAME` та `PASSWORD` на відповідні значення для вашого PostgreSQL.

### Запуск

Клонуйте репозиторій:

```bash
git clone git@github.com:flamylight/ConferenceBooking.git
cd ConferenceBooking
```

Запустіть застосунок:

```bash
dotnet run --project ConferenceBooking.API
```

Під час першого запуску застосунок автоматично застосовує необхідні EF Core міграції та виконує початкове заповнення бази даних (seed).

Після успішного запуску API буде доступне за адресою, вказаною в консолі.

### Swagger

Після запуску застосунку Swagger UI доступний за адресою:

```text
https://localhost:<PORT>/swagger
```

Swagger дозволяє переглянути доступні API endpoints, структуру запитів і відповідей, а також виконувати HTTP-запити безпосередньо через браузер.
